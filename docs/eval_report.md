## v3: BM25 vs hybrid และสิ่งที่ยังพัง

**Vector search ไม่ได้ช่วย** (70/75 เท่ากัน) เพราะ agent เป็นคนเขียน query และกำหนด `top_k` เอง

**q14 ลาพักร้อน 0/5 ทั้งสองรอบ**
- agent ส่ง `top_k=1` ทุกครั้งที่ค้นใน q14 (70 ครั้ง รวมสองรอบ) จึงเห็นแค่มาตราอันดับ 1 เสมอ (คำถามอื่นส่วนใหญ่ใช้ 3 หรือ 5)
- ค้นคำชุดเดิมซ้ำ เช่น "ลาพักร้อน จำนวนวัน ปี" 3 ครั้งติด ไม่เปลี่ยนคำ
- คำในชีวิตประจำวัน "ลาพักร้อน" ไม่ตรงกับศัพท์ตัวบท "หยุดพักผ่อนประจำปี" (มาตรา 30)
- ทดสอบ BM25 ในเครื่อง: "หยุดพักผ่อนประจำปี" ได้มาตรา 30 อันดับ 1 · "จ่ายเงินเดือน จำนวนครั้ง" ได้มาตรา 70 อันดับ 2 ซึ่งถูกตัดทิ้งเมื่อ top_k=1

**q13 hybrid รอบที่ 4 อ้างมาตราผิดแต่ผ่าน policy**
- ตอบ "จ่ายค่าจ้างไม่น้อยกว่าเดือนละหนึ่งครั้ง ตามมาตรา 96" แต่มาตรา 96 คือเรื่องคณะกรรมการสวัสดิการ (กฎนี้อยู่ในมาตรา 70)
- ผ่านกฎทั้ง 5 ข้อ เพราะมาตรา 96 มีจริง ถูกดึงมาเป็น context และ quote คัดลอกตรงตัว
- behavior ok ยังนับ 5/5 · จับได้จาก recall (0 ในรอบนั้น) เท่านั้น
- สรุป: กฎเดิมตรวจได้ว่าการอ้างอิง "มีจริง" แต่ไม่ได้ตรวจว่ามาตรานั้น "รองรับข้อความ" ที่ตอบ

## v4: สิ่งที่เปลี่ยน

| กลไก | ชั้น | แก้ปัญหาอะไร | ตั้งค่า |
|---|---|---|---|
| top_k ขั้นต่ำ | tool argument guard | q14/q13: โมเดลขอ top_k=1 จนมองไม่เห็นมาตราที่ถูก | `MIN_TOP_K` (ค่าเริ่มต้น = `TOP_K`) |
| กันค้นซ้ำ | tool result | ค้นคำชุดเดิม (สลับลำดับคำก็นับ) → ไม่ค้นใหม่ ส่งผลเดิม + แนะนำให้เปลี่ยนคำ | `DUPLICATE_QUERY=skip\|allow` |
| `NUMBER_GROUNDED` | policy | q13→96: ตัวเลขที่มีหน่วยในคำตอบต้องพบในมาตราที่อ้าง หรือในข้อความผู้ใช้ | `data/citation_policy.json` |
| `issue_type` | tool schema | วัดการจำแนกประเด็นกฎหมายได้ตรง ๆ | enum จาก `data/agencies.json` + `out_of_scope` |
| LLM judge | eval | วัด faithfulness รายประโยค โดยโมเดลที่สามซึ่งไม่ใช่ตัวที่ถูกประเมิน | `--judge-model` |

**ทดสอบ `NUMBER_GROUNDED` ย้อนหลังก่อนเปิดเป็น block** (`python scripts/backtest_number_grounded.py`)
ใช้คำตอบจริงจาก v1–v3 ทั้งหมด 168 คำตอบที่มีการอ้างมาตรา (136 คำตอบมีตัวเลขพร้อมหน่วย)

| รอบ | คำตอบที่ตรวจ | กฎจะตีกลับ |
|---|---|---|
| v1 | 31 | 0 |
| v2 | 34 | 0 |
| v3-bm25 | 51 | 0 |
| v3-hybrid | 52 | 1 — q13 รอบ 4 ที่อ้างมาตรา 96 ("หนึ่งครั้ง" ไม่มีในมาตรา 96) |

ไม่มี false positive ในคำตอบที่ถูกอยู่แล้ว และจับเคสที่ตั้งใจจะจับได้

v4 เปลี่ยนหลายกลไกพร้อมกัน ผลรวมจึงไม่ได้บอกว่าดีขึ้นเพราะกลไกไหน ให้ดูจาก harness stats ว่าแต่ละกลไกทำงานกี่ครั้งในข้อไหน
ถ้าต้องการแยกผลทีละกลไก รันซ้ำโดยปิดทีละตัว เช่น `MIN_TOP_K=1 DUPLICATE_QUERY=allow python eval/run_eval.py --tag v4-no-guard`

## ข้อจำกัดของการวัด

- gold sections และ key facts เป็นร่าง ยังไม่ผ่านผู้มีความรู้กฎหมาย
- key facts ใช้การหาคำ คำตอบที่ถูกแต่เขียนต่างรูปอาจถูกนับว่าขาด (เช่น q12 ไม่เขียนเวลา 22.00)

- 15 ข้อ × 5 รอบ เล็กเกินกว่าจะสรุปเชิงสถิติ ใช้ดูรูปแบบความล้มเหลวเป็นหลัก
