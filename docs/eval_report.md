## v3: BM25 vs hybrid และสิ่งที่ยังพัง

**Vector search ไม่ได้ช่วย** (70/75 เท่ากัน) เพราะ agent เป็นคนเขียน query และกำหนด `top_k` เอง

**q14 ลาพักร้อน 0/5 ทั้งสองรอบ**
- agent ส่ง `top_k=1` ทุกครั้งที่ค้นใน q14 (70 ครั้ง รวมสองรอบ) จึงเห็นแค่มาตราอันดับ 1 เสมอ (คำถามอื่นส่วนใหญ่ใช้ 3 หรือ 5)
- ค้นคำชุดเดิมซ้ำ เช่น "ลาพักร้อน จำนวนวัน ปี" 3 ครั้งติด ไม่เปลี่ยนคำ
- คำในชีวิตประจำวัน "ลาพักร้อน" ไม่ตรงกับศัพท์ตัวบท "หยุดพักผ่อนประจำปี" (มาตรา 30)
- ทดสอบ BM25 ในเครื่อง: "หยุดพักผ่อนประจำปี" ได้มาตรา 30 อันดับ 1 · "จ่ายเงินเดือน จำนวนครั้ง" ได้มาตรา 70 อันดับ 2 ซึ่งถูกตัดทิ้งเมื่อ top_k=1

**q13 hybrid รอบที่ 4 อ้างมาตราผิดแต่ผ่าน policy**
- ตอบ "จ่ายค่าจ้างไม่น้อยกว่าเดือนละหนึ่งครั้ง ตามมาตรา 96" แต่มาตรา 96 คือเรื่องคณะกรรมการสวัสดิการ (กฎนี้อยู่ในมาตรา 70)
- ผ่านกฎทั้ง 5 ข้อ เพราะมาตรา 96 มีจริง ถูกดึงมาเป็น context และ quote คัดลอกตรงตัว
- behavior ok ยังนับ 5/5 · จับได้จาก recall (0 ในรอบนั้น) เท่านั้น
- สรุป: กฎเดิมตรวจได้ว่าการอ้างอิง "มีจริง" แต่ไม่ได้ตรวจว่ามาตรานั้น "รองรับข้อความ" ที่ตอบ

## v4: สิ่งที่เปลี่ยน

| กลไก | ชั้น | แก้ปัญหาอะไร | ตั้งค่า |

| top_k ขั้นต่ำ | tool argument guard | q14/q13: โมเดลขอ top_k=1 จนมองไม่เห็นมาตราที่ถูก | `MIN_TOP_K` (ค่าเริ่มต้น = `TOP_K`) |
| กันค้นซ้ำ | tool result | ค้นคำชุดเดิม (สลับลำดับคำก็นับ) → ไม่ค้นใหม่ ส่งผลเดิม + แนะนำให้เปลี่ยนคำ | `DUPLICATE_QUERY=skip\|allow` |

| LLM judge | eval | วัด faithfulness รายประโยค โดยโมเดลที่สามซึ่งไม่ใช่ตัวที่ถูกประเมิน | `--judge-model` |

### อ่านผล

**open-source ไม่แพ้ commercial ภายใต้ harness เดียวกัน** Qwen3 ได้ behavior ok 72/75 ส่วน gpt-4.1-mini ได้ 64/75 ต้นทุนต่อคำถามเท่ากัน
เพราะ gpt-4.1-mini ใช้ token น้อยกว่า แต่ราคาต่อ token แพงกว่า ข้อที่ gpt-4.1-mini ดีกว่าชัดเจนคือเร็วกว่า 3 เท่า

ที่ gpt-4.1-mini เสียคะแนนไม่ใช่เพราะอ้างผิด แต่เพราะ **ถามกลับเกินจำเป็น** (need_more_facts 23 รอบ เทียบกับ 13 รอบของ Qwen3)
- q08 จำแนกถูกว่า `out_of_scope` ครบ 5/5 แต่ไปเรียก `request_more_facts` แทนการตอบว่านอกขอบเขต
  แปลว่าจำแนกประเด็นถูก แต่เลือก tool ปิดรอบผิด
- q11 ถาม "เหตุผลที่ถูกไล่ออกคืออะไร" ทั้งที่ผู้ใช้บอกแล้วว่า "ไม่ได้ทำผิดอะไร"

**q14 ผ่านแล้ว แต่ไม่ได้ผ่านเพราะ retrieval ดีขึ้น** เรื่องนี้เห็นได้จาก trajectory เท่านั้น ดูแค่คะแนนจะไม่เห็น
- ทั้งสองรอบ ผลค้น "ลาพักร้อน" ด้วย hybrid top 5 **ยังไม่มีมาตรา 30 เลย** แปลว่า bge-m3 ไม่ได้เชื่อมคำว่า "ลาพักร้อน" เข้ากับ "หยุดพักผ่อนประจำปี"
- gpt-4.1-mini ค้น "ลาพักร้อน" ได้มาตรา 67 ซึ่งในตัวบทเขียนว่า "...ตามมาตรา ๓๐" แล้วจึงดึงมาตรา 30 มาอ่าน (ไปตามการอ้างอิงในตัวบท ถือว่าใช้ได้)
- Qwen3 ค้น "ลาพักร้อน จำนวนวัน" ไม่ได้มาตรา 67 จึงไล่ดึงมาตรา 31, 32, 33... ทีละชุดจนเจอ 30 และมีอยู่รอบหนึ่งที่ดึงมาตรา 30 ตรงๆ โดยไม่ค้นเลย
  (ใช้ความรู้ของโมเดลเองว่าควรดูมาตราไหน แต่ข้อความที่ตอบยังมาจากตัวบทที่ดึงมาจริง)
- สรุป: ปัญหาคำในชีวิตประจำวันไม่ตรงกับศัพท์ตัวบทยังอยู่ ต้องแก้ที่ retrieval ด้วย term mapping / ontology ไม่ควรพึ่งให้โมเดลจำเลขมาตราเอง

**กลไกไหนทำงานจริง (จาก harness stats และ trajectory)**
- `MIN_TOP_K` แทบไม่ได้ทำงานเลย (ถูกบังคับ 0 ครั้ง) เพราะคำอธิบาย tool ที่แก้ใหม่บอกว่า "ระบบคืนอย่างน้อย 5" โมเดลจึงขอ `top_k=5` เองทุกครั้ง
  สิ่งที่ช่วยคือการแก้คำอธิบาย tool ไม่ใช่โค้ดที่บังคับ แต่ยังเก็บโค้ดไว้เป็นตัวกันพลาด
- ค้นคำชุดเดิมซ้ำ: v3 เจอ 18–21 ครั้ง v4 เจอ 0 ครั้ง ตัวกันค้นซ้ำจึงไม่ได้ทำงานเหมือนกัน เพราะโมเดลไม่ค้นซ้ำตั้งแต่แรก
- `NUMBER_GROUNDED` ไม่ได้ตีกลับเลยในรอบนี้ ไม่มีคำตอบไหนให้ตัวเลขที่ไม่มีในมาตราที่อ้าง ยังเก็บไว้เป็นตัวกันเคสแบบ q13→96
- tool call errors (argument เป็น JSON ที่ขาดกลางคัน) v3 เจอ 8 ครั้ง v4 เจอ 0 ครั้ง สงสัยว่าเกี่ยวกับการตัด `frequency_penalty`
  (มันลงโทษ token ที่ซ้ำ รวมถึงเครื่องหมาย `"` ที่ JSON ใช้บ่อย) แต่ยังเป็นแค่สมมติฐาน เพราะ v4 เปลี่ยนหลายอย่างพร้อมกัน

**judge: อ่านประโยคที่ถูกตั้งข้อสังเกตทีละประโยค** (Qwen3 10 คำตอบ, gpt-4.1-mini 2 คำตอบ)

| ประเภท | ตัวอย่าง | นับเป็นปัญหาจริงไหม |
|---|---|---|
| ข้อมูลฉบับแก้ไข | "แก้ไขเพิ่มเติมโดย (ฉบับที่ 9) พ.ศ. 2568" | ไม่ — มาจาก `amendment_notes` ที่ tool คืนมา แต่ judge เห็นเฉพาะตัวบท |
| ประโยคบอกว่าไม่มี / นอกขอบเขต | "ไม่พบมาตรา 999", "ไม่อยู่ในขอบเขตของ พ.ร.บ.นี้" | ไม่ — เป็นข้อเท็จจริงเกี่ยวกับฐานข้อมูล ไม่ได้อ้างตัวบท |
| ความรู้กฎหมายนอกตัวบท | "การรุกที่ดินเป็นเรื่องกฎหมายแพ่ง", "โบนัสขึ้นอยู่กับสัญญาจ้าง" | **ใช่ (เล็กน้อย)** — ผิดกฎ prompt ข้อ 1 |
| สรุปเกินตัวบท | "ระยะเวลาที่เกิน 60 วันจะไม่ได้รับค่าจ้าง" (q01) | **ใช่** — ตัวบทบอกแค่ว่านายจ้างจ่ายไม่เกิน 60 วัน ไม่ได้บอกว่าวันที่เหลือไม่ได้อะไรเลย |

สิ่งที่ควรแก้ต่อ: ส่ง `amendment_notes` ให้ judge เห็นด้วย และให้ judge แยกประโยคบอกขอบเขตออกจากประโยคที่อ้างตัวบท

**issue type ที่ไม่ตรง** gpt-4.1-mini ให้ q07 (หักค่าจ้าง) และ q13 (กำหนดจ่ายค่าจ้าง) เป็น `general` แทน `unpaid_wages`
ส่วนหนึ่งเป็นปัญหาของชื่อหมวด เพราะ `unpaid_wages` แคบกว่าเรื่องค่าจ้างทั้งหมด ควรให้ผู้มีความรู้กฎหมายช่วยทบทวนหมวดด้วย

## ข้อจำกัดของการวัด

- gold sections และ key facts เป็นร่าง ยังไม่ผ่านผู้มีความรู้กฎหมาย
- key facts ใช้การหาคำ คำตอบที่ถูกแต่เขียนต่างรูปอาจถูกนับว่าขาด (เช่น q12 ไม่เขียนเวลา 22.00)
- judge เป็น LLM ใช้เป็นสัญญาณเตือน ไม่ใช่คำตัดสินสุดท้าย ประโยคที่ judge ว่าไม่รองรับถูกเก็บไว้ให้คนอ่านซ้ำ
- 15 ข้อ × 5 รอบ เล็กเกินกว่าจะสรุปเชิงสถิติ ใช้ดูรูปแบบความล้มเหลวเป็นหลัก
- เทียบ commercial แค่โมเดลเดียว (gpt-4.1-mini) ผลไม่ได้แทน commercial ทุกตัว
- trajectory ของรอบก่อน v4 ได้มาจากการจับคู่ log กับผล eval ตามลำดับเวลา (จับคู่ได้ครบทุกแถว และมาตราที่อ้างตรงกันทุกแถว)
